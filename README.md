# 阶段 1 · 裸问答原型（RAG）

海岳机电 · 设备点检与维修协同项目。目标不是"做个能聊天的机器人"，而是回答一个问题：

> **从维修手册、历史案例、备件清单里，能不能稳定捞出正确依据，并且让一线能核对？**

跑得通才进阶段 2；跑不通就先修检索，不要往下铺功能。

## 1. 快速开始

```bash
cd output/20261030-stage1-rag
python -m pip install -r requirements.txt   # 只有 jieba / httpx，都可缺省

python rag_proto.py ingest                     # 建索引
python rag_proto.py ask "M-0912 主轴出现异响，怎么判断是不是轴承磨损？" --trace
python rag_proto.py ask "BRG-6204 有替代型号吗？"
```

## 4. 四个关键设计决策

**① 章节边界优先于填满 300–500 token**
本语料单节多在 80–250 token。强行合并相邻章节能让块更"饱满"，但引用会指到 `§4` 而不是 `§4.1`——技师按 `§4.1` 去翻力矩表，翻到的是"拆装概述"。宁可块小，不可引用含糊。
超长节才做窗口切分，重叠 12%。

**② 表格整块保留，超长才按行切且复制表头**
`| 前端轴承压盖 | M8×25 | 45 ± 5 N·m |` 一旦被切成两半，模型看到的是一堆没有列名的数字，答案就是错的。这类错误的代价比召回率低一个点高得多。
实测语料里 6 个表格块全部完整保留。

**③ 标题块不单独建索引**
第一版把 `### 4.1 轴承预紧力矩` 单独切成了 6 token 的块，既占召回位、又让表格块的文本里没有章节名。现在标题会拼到紧随其后的表格前。

**④ 拒答用两道闸门，不用单一相似度**
- `confidence = 0.45 * 余弦 + 0.55 * IDF 加权覆盖`
- 任一低于阈值即拒答，**在调用模型之前**就拦住

为什么不用单一余弦：本地哈希向量下，正确答案的余弦可能只有 0.13（Q10 问"振动多少停机"，参数表全是数字，语义向量几乎无信号），而无关问题也能到 0.20。单看余弦，无法同时做到"该答的答、该拒的拒"。

为什么覆盖度要按 IDF 加权：命中「挂牌」「解除」这类低频词，比命中「主轴」这种满篇都是的词更能说明找对了片段。等权覆盖会把泛词算重，负样本全被放行（第一版就是这么翻车的，负样本拒答率 0%）。

## 5. 检索链路（可调参数都在 `CONFIG`）

```
问题
 ├─ jieba 分词 → 去停用词 → 领域同义词扩词（仅用于 BM25 召回）
 ├─ BM25（k1=1.5, b=0.75）top20 ─┐
 ├─ 向量余弦 top20 ──────────────┼─ 加权 RRF（0.65 / 0.35）→ 候选 20
 └────────────────────────────────┘
        ↓ 重排：0.40*cos + 0.35*IDF覆盖 + 0.25*BM25归一 + 机型匹配/跨机型惩罚 + 文档类型先验
        ↓ 取 top3
   [拒答闸门] confidence < 0.20 或 coverage < 0.20 → 转人工
        ↓ 通过
   拼提示词（每条资料带 文档编号/章节/版本）→ LLM → 引用校验 → 输出
```

**文档类型先验**：问"怎么判断/标准是多少"时手册是规范、案例只是先例；问"上次/历史怎么处理"时反过来；问"安全/挂牌/措施"时安全规程优先（+0.10）。没有这一层，案例片段经常把手册挤到第 3 位（本机实测 Q01 出现过）。

**跨机型惩罚**：问题点名了机型时，其他机型的段落扣 0.06。修复前问「M-0912 换轴承的安全措施」，第 3 条答案是 H-1023 的「维修记录要求」——用另一台设备的要求当本机依据，这类错误的危害远大于排名靠后。

**为什么 `recall_k` 从 10 提到 20**：语料 46 块时取 10，安全规程 7 个块全部落选——它们与问题只共享"主轴"这一个满篇都是的泛词。召回池放大到 20 后，§2「停机与挂牌步骤」从"不在候选池"升到第 6，但要进 top3 仍需真实语义向量（见局限 1）。

**权重 0.65 / 0.35 是临时值**：因为当前向量是字符哈希实现，语义能力弱。换成 `bge-m3` 或 `text-embedding-3` 之后应回调到 0.5 / 0.5，并重跑评测。

## 6. 已知局限（按严重程度排序）

1. **向量是字符 n-gram 哈希，不是语义模型。** 同义表述（"异响" vs "噪声"）召回不了；更典型的是问「安全措施」而规程里写「停机与挂牌步骤」——字面几乎不重合，语义高度相关，当前排到第 6 进不了 top3。接真实 embedding 后 Q03 这类问题会明显改善。
2. **评测集只有 15 条，且被用于标定阈值。** 见第 2 节的警告。
3. **`PgVectorStore` 未经运行验证。** 本机无 PG 实例，代码只保证接口与 `LiteStore` 对齐。上线前必须实测，并确认中文全文检索装 `zhparser`（当前用 `simple` + 预分词绕过）。
4. **mock 生成器只做抽取，不判断。** 它证明的是"检索 + 引用链路"成立，不能证明模型会老实按资料回答。忠实度必须用真实模型重测。
5. **语料是合成样例。** 结构与真实手册一致（步骤、参数表、警告框、案例字段），但内容需替换为真实文档后重跑，届时切片参数与阈值都要重标。
6. **没有多轮对话。** 阶段 1 刻意不做，指代消解（"那它呢"）留到阶段 2 和工具调用一起做。

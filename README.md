# 海岳机电 · 点检维保问答服务（阶段 2）

阶段 1 是命令行原型（`../20261030-stage1-rag/`）。本服务把那条检索链搬到一个 HTTP 服务上，
加上会话、流式输出、引用与鉴权，给技师一个能用的问答入口。

技术栈：FastAPI（异步）+ SQLite（会话与消息）+ 复用阶段 1 的检索/提示词/引用校验。
向量与索引仍在阶段 1 的 `data/index.sqlite3` 里，本服务只读。

## 二、接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/auth/login` | 登录，返回 JWT |
| POST | `/api/v1/chat` | 提问，SSE 流式返回（`?debug=1` 附带内部指标） |
| GET | `/api/v1/sessions` | 会话列表（最近 20 条） |
| GET | `/api/v1/sessions/{id}/messages` | 历史消息 + 引用 |
| DELETE | `/api/v1/sessions/{id}` | 关闭会话（软删，`status=closed`） |
| GET | `/api/v1/citations/{chunk_id}` | 引用原文 + 前后各 1 块 |
| GET | `/api/v1/health` | 健康检查（含知识库就绪状态） |

非 SSE 接口统一信封：`{code, message, data, request_id}`，`code=0` 为成功。
成功码只在验收脚本里用数字，界面上永远展示 `message`（中文）。

### SSE 事件

顺序固定为 `meta → status → delta* → citation* → done`，异常时为 `error`（`done` 不再发）。

| 事件 | 载荷 | 说明 |
|---|---|---|
| `meta` | `session_id, message_id, request_id` | 首帧，锁定气泡与报障 id |
| `status` | `stage, text` | `retrieving` / `generating`，驱动「正在检索…」 |
| `delta` | `text` | 增量文本，客户端追加 |
| `citation` | `index, chunk_id, source_id, section_path, version, snippet, score?` | 正文发完后逐条下发 |
| `done` | `refused, refusal_reason, usage, elapsed_ms` | 收尾 |
| `error` | `code, message` | 故障 |

三条硬规则：

1. **拒答走 `done` 不走 `error`**。「资料中未找到依据」是业务结果，混进 error 会把正常拒答算进故障率。
2. **引用单独下发，不靠正则解析正文**。正文里的 `[1][2]` 只是锚点。
3. **每 15 秒一行 `: ping`**，否则 Nginx 60 秒空闲断流，用户看到「答一半停了」。

### 错误码

| code | HTTP | 场景 |
|---|---|---|
| 40001 / 40002 | 400 | 问题为空 / 超 500 字 |
| 40101 | 401 | 未登录或 token 过期 |
| 40301 / 40302 | 403 | 无权访问该会话 / 设备不在数据域 |
| 40401 | 404 | 会话不存在或已关闭 |
| 42901 | 429 | 单用户 10 次/分钟 |
| 50001 / 50002 / 50003 | 500 | 检索不可用 / 模型超时 / 知识库未就绪 |

## 三、这次实现里值得记的几个决定

**1. 上下文只带纯文本，不带引用。**
把历史里的 `[来源: MAN-M0912-001 §4.1 | V3.2]` 塞回提示词，模型会直接复述上一轮引用，
绕过本轮检索——问 A 设备得到 B 设备的依据。所以历史只回放用户问题和答案正文。

**2. 6 轮是上限，不是目标。**
按 1500 token 预算裁，超了整轮丢弃（不切半轮），否则问答会错位。

**3. 指代改写发生在检索侧，不在界面。**
问题少于 8 字或含「它/这个/那」时，用「上一轮问题 + 本轮问题」拼接去检索，界面仍显示用户原话。

**4. 打字机的切片不丢换行。**
第一版按标点切片，把 `\n` 一起吃掉了，前端因此认不出列表项，`- xxx` 全挤成一段。
现在切片保证 `''.join(pieces) == 原文`，改成流式后仍能正确渲染列表与表格。

**5. 引用卡片与正文编号必须同源。**
编号以「正文出现顺序」为准，服务端返回的 items 只用来补 snippet 和 chunk_id。
反过来做（用服务端顺序编号）会出现「正文标 [1]，卡片却是另一篇」的错位。

**6. 引用原文弹层里的表格要渲染成真表格。**
用 `│` 拼纯文本在比例字体下对不齐，力矩表会串行——技师把「后端 25 N·m」看成「主轴法兰 80 N·m」
是要出事的。所以弹层把 markdown 表格转成 `<table>`，其余内容只做轻量排版，不改原措辞。

**7. 空态要给示例问题。**
打开就是一片空白，技师不知道能问什么，会当成坏了。示例按四类语料各给一条（参数/判断/安全/案例/备件），
顺带说明了这个助手的边界：只答这四类资料。

## 四、已知局限

1. **模型是 mock。** 现在的「生成」是从检索到的片段里抽句拼装，证明的是检索+引用+流式链路，
   不证明模型忠实度。换真模型只需改环境变量：`LLM_PROVIDER=openai_compat` + `LLM_BASE_URL/API_KEY/MODEL`，
   代码路径已经打通（`app/rag.py::_stream_openai`）。
2. **账号是种子数据。** 两个人写死在 `app/db.py`，密码用 PBKDF2 哈希校验（不是明文），
   但没有注册、改密、锁定、审计。接企业账号体系前必须换掉。
3. **数据域只做「点名拦截」。** 问题里点了别的作业区的设备型号会返回 40302；
   但检索结果没有按作业区过滤——因为 `data_scope` 表还没落地，
   现在过滤会把安全规程、备件清单这类跨机型资料一起挡掉，反而让技师问「换轴承的安全措施」得到「未找到依据」。
   库级行过滤等设备台账接入后再开（`app/scope.py` 的 `MODEL_AREA` 就是那个替换点）。
4. **管理员端没做。** 本轮只有问答入口；知识库管理、审计查询、质量修复队列属于阶段 3。
5. **会话存在 SQLite**，单文件。并发写多时会锁，试点 10 台设备的量级够用，扩容要换 PostgreSQL。
6. **拒答阈值沿用阶段 1 的标定值**（confidence 0.20 / coverage 0.20），样本 15 条，偏乐观。

## 五、文件说明

```
app/
  config.py     环境配置（LLM provider、阈值、库路径）
  errors.py     错误码表 + 统一异常处理
  security.py   JWT 签发校验、演示用户、角色判定
  db.py         SQLite 连接与建表（conversations/messages/message_citations）
  store.py      会话与消息的读写，含 6 轮上下文裁剪
  rag.py        桥接阶段 1：检索、提示词、引用解析与校验、真流式
  deps.py       依赖注入：当前用户、请求 id
  scope.py      数据域判定（型号 → 作业区占位映射，接入台账后替换）
  routes/
    auth.py     登录
    chat.py     SSE 主接口 + 会话/引用/健康检查
  main.py       create_app，中间件顺序即安全边界
static/index.html   单页界面（原生 JS，无框架）
scripts/smoke.py    33 项端到端自检
```
